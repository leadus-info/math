## 引き算とは何か

こんな場面を考えてみましょう。

> たかしくんは最初に何個かのりんごを持っています。\
> お母さんから3個もらったので、数えてみたら全部で7個でした。\
> 最初に持っていたのは何個でしょう？

「もらった後の個数」と「もらった個数」はわかっています。わからないのは「最初の個数」です。\
これを足し算の式で書くと、こうなります。

$$\boxed{?} + 3 = 7$$

この$\boxed{?}$は、たかしくんが最初に持っていたりんごの数であり、「3を足すと7になる数」です。\
どんな数なら当てはまるか調べるために、1から順に$\boxed{?}$に当てはめて試してみると、4を入れたとき $4 + 3 = 7$ で成り立ちます。\
そのため、最初にたかしくんが持っていたりんごの数は4個だとわかるのです。

このように、「3を足した時に7になる数」を求める計算を**引き算**と呼びます。この引き算は$7 - 3$という式で表します。\
この式の中で、$7$を**引かれる数**、$3$を**引く数**と呼びます。

$$7 - 3 = 4$$

引き算は足し算の空欄を埋める計算なので、**足し算の逆操作**にあたります。\
ここで少し一般化すると、ある操作をした後の結果から、操作を行う前の状態を求め直すことを、逆操作と呼びます。\
今回の例で言えば、「3を足す」という操作の結果(7)から操作前の数(4)を求めているので、これはまさに足し算の逆操作にあたっているのです。

引き算が使われる場面は、これだけではありません。「7個から3個取ると残りは何個か」のように、何かを取り除いた後の残りを求める場面（**求残**（きゅうざん））でも、引き算が使われます。\
取った3個と残った$\boxed{?}$個を合わせると、ちょうど元の7個になります。\
つまり「取った数」と「残りの数」を合わせると「最初の数」になるという関係があるため、この場面でも、7が最初の数、$\boxed{?}$が取った後に残る数にあたり、$\boxed{?} + 3 = 7$という、先ほどの例と全く同じ形の式で表せます。\
つまりこの$\boxed{?}$も、先ほどの例と同じように足し算の空欄を埋めることで求めているのであり、これもやはり足し算の逆操作にあたっているのです。




## 数直線の上を左に進む

はじめのりんごの例（$\boxed{?} + 3 = 7$）に戻って、今度は数直線を使って眺めてみましょう。

[足し算](addition.md)では、数直線のはじめの数の位置から出発して、足す数の分だけ目盛りを右に進むと、答えの位置に着くのでした。\
この見方で$\boxed{?} + 3 = 7$を読むと、「$\boxed{?}$の位置から目盛り3つ分だけ右に進むと、7に着く」となります。\
着く場所が7だとわかっていて、知りたいのは出発した場所です。

そこで、進んだ道を逆向きにたどってみましょう。7の位置から目盛り3つ分だけ左に戻る（＝左に進む）と、出発した場所に着くはずです。\
7から目盛りひとつ分だけ左に進むと6、もうひとつ左に進むと5、さらにもうひとつ左に進むと4です。\
たしかに出発点の4に着きました。これが$7 - 3 = 4$です。

![1から始まる数直線を上下2段に並べ、上段は4の位置から目盛り3つ分だけ右に進んで7に着き、下段は7の位置から目盛り3つ分だけ左に進んで4に着くことを、1目盛りごとの矢印で示した図](subtraction/images/number-line-subtract-7-minus-3.svg)

このように、引く数の分だけ目盛りを左に進むと、答えの位置に着きます。

> [!IMPORTANT]
> 引き算は、数直線の引かれる数の位置から出発して、引く数の分だけ目盛りを左に進むことと同じである。




## 差を求める引き算

場面の話に戻りましょう。引き算には、もう1つよく使われる場面があります。

> たかしくんはりんごを7個、はなこさんはりんごを3個持っています。\
> たかしくんははなこさんより何個多く持っているでしょう？

この問題は、次のように言い換えることができます。

> たかしくんはりんごを7個、はなこさんはりんごを3個持っています。\
> はなこさんがあと何個のりんごを持っていれば、二人が持っているりんごの数は等しくなるでしょう。

はなこさんが追加でもらう個数は、ちょうど二人の個数の差の分だけです。たかしくんが多く持っている分をそっくり埋め合わせれば、そこで二人の個数がぴったり等しくなるからです。

つまり、「たかしくんの方が何個多いか」という問いと、「はなこさんが何個もらえば等しくなるか」という問いは、同じ個数を尋ねている同じ問いなのです。\
はなこさんは3個、たかしくんは7個のりんごを持っています。はなこさんの持っている個数に何個か足すと、たかしくんの持っている個数と等しくなるので、次の式が成り立ちます。

$$3 + \boxed{?} = 7$$

足し算は、足す数と足される数の順番を入れ替えても答えが変わりません。これを**交換法則**と呼びます。\
この交換法則を使ってさきほどの式の順番を入れ替えると、$\boxed{?} + 3 = 7$となり、これは「引き算とは何か」で見た式と同じ形だと言えます。\
つまり、「3を足したら7になる数はいくつでしょう」と聞かれているのと同じです。\
したがって、答えは$4$になります。

$$7 - 3 = 4$$

ここでは、たかしくんの個数$7$が引かれる数、はなこさんの個数$3$が引く数にあたります。\
このように、引き算は二つの数の**差を求める**（**求差**（きゅうさ））ときにも使うことができます。\
大きな数から小さな数を引くと、二つの数の差を計算することができるのです。





## 引き算ができないとき

引き算にはうまくいかない場合があります。

$$\boxed{?} + 5 = 3$$

$\boxed{?}$ に当てはまる[自然数](natural-numbers.md)（ものを数えるときに使う$1, 2, 3, 4, \ldots$のような数）はありません。「5を足したら3になる自然数」は存在しないのです。これは、引き算の式で言うと$3 - 5$（引かれる数が$3$、引く数が$5$）を計算しようとしていることに対応します。

この行き詰まりは、数直線で見ると目で確かめられます。$3 - 5$は3の位置から目盛り5つ分だけ左に進むということですが、2、1と進んだところで目盛りがなくなってしまいます。\
1より小さい自然数はないため数直線の左端は1であり、それより左には自然数が並んでいないので、5つ分を進み切ることができないのです。

![1から始まる数直線上で、3の位置から目盛りを左に進むと2、1と進めるが、1より左には目盛りがなくそれ以上進めないことを、破線の矢印で示した図](subtraction/images/number-line-subtract-wall.svg)

引く数と引かれる数が等しい場合にも、同じように答えが出せません。

$$\boxed{?} + 3 = 3$$

この$\boxed{?}$に当てはまる数は$0$しかありませんが、[自然数](natural-numbers.md)には$0$を含めないため、自然数の範囲では答えが求められないのです。先ほどの例（$\boxed{?} + 5 = 3$）は、条件を満たす数自体が自然数の中に存在しませんでした。\
一方この例では、$0$という条件を満たす数は存在するものの、それが自然数ではないために成り立ちません。

この場合も数直線で見ると、3の位置から目盛り3つ分だけ左に進もうとすることになりますが、2、1と進んだところで目盛りがなくなり、3つ目の一歩の行き先が数直線の上にありません。\
式の上では$0$という答えの候補がありますが、$0$は自然数ではないため、自然数を並べたこの数直線には現れません。\
進み先が見つからないのは、そのためです。

このように、引く数が引かれる数より大きいとき、または等しいとき、自然数の範囲では答えを求めることができません。

中学校になると、この問題を解消するために**負数**を新しく定義し、数直線を1より左にも延ばします。\
そこには$0$も、$0$より小さい負数も並ぶので、どんな引き算でも答えが出るようになります。\
この負数については、[負数](../../intermediate/numbers/integers.md)で詳しく扱います。





## まとめ

引き算は「足し算の空欄を埋める操作」として定義され、足し算の逆操作にあたります。\
この引き算は、残りを求める場面（求残）や、2つの量を比べて差を求める場面（求差）にも使えます。\
また、数直線の引かれる数の位置から、引く数の分だけ目盛りを左に進む移動として見ることもできます。\
ただし[自然数](natural-numbers.md)の範囲では、1より左には自然数が並んでいないため、引く数が引かれる数より大きいとき、または等しいとき（差が$0$になるとき）、答えが出ません。\
この限界を超えるために、数学では負数という新しい数が定義されました。
